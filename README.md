# content_gen — редакционная система для Telegram

Самостоятельное Python-приложение для сбора сообщений из Telegram-каналов, подготовки новостей через LLM, редакторской модерации и публикации. В одном процессе работают веб-панель, общий аккаунт-читатель, общий бот публикации и планировщик. SQLite хранит настройки, сессии, источники, черновики, историю и отчёты о записанных расходах.

Система поддерживает несколько независимых **редакционных пространств**: у каждого свои источники, канал назначения, модель, характер автора, расписание, модули и контент-план. Это не отдельные Telegram-аккаунты и не разграничение прав разных пользователей.

## Возможности

- **Новостной поток.** Инкрементальный сбор из выбранных каналов, фильтр коротких сообщений и стоп-слов, подготовка нескольких разных новостей по источникам, ссылки на оригиналы и список ранее предложенных тем в контексте модели.
- **Редакторское управление.** Одобрение, отклонение, переписывание и ручная правка в панели или в личном чате с ботом. Автопубликация новостей выключена по умолчанию; её включение — отдельное решение оператора.
- **ИИ-прогноз.** Для новых и переписываемых новостей — явно обозначенный условный вывод модели, с настраиваемым горизонтом, длиной и фокусом. Включён по умолчанию (`news_outlook_enabled=1`) для каждого пространства, но блок появляется только при пригодном ответе модели. Если прогноз отсутствует, некорректен, небезопасен, чрезмерно длинен или не подкреплён источниками, остаются фактическая статья и её хэштеги — без метки, диагностики и общего редакционного шаблона. Отдельного запроса, повторной попытки или дополнительного расхода ради отсутствующего прогноза нет; старые тексты автоматически не переписываются.
- **Подача текста.** Характер автора, язык, длина, стиль, шаблон промпта, эмодзи, заголовок и выборочное **жирное** выделение. Тематические хэштеги статьи и служебные метки пространства имеют разное назначение.
- **Дополнительные модули.** Фото из источников, очередь по временным слотам, примеры редакторских правок в промпте и эвристическое обнаружение срочных событий. Модули включаются отдельно в каждом пространстве.
- **Независимый контент-план.** Темы и заметки владельца, будущие даты, подготовка статьи и необязательной анимированной инфографики MP4. Доступен общий OpenAI-совместимый провайдер либо отдельное подключение Anthropic. Автоматическое исполнение плана имеет собственную паузу и не зависит от паузы новостей.
- **Наблюдаемость.** Статусы подключений, черновики, очередь, история решений, журнал событий, отчёты по циклам и отдельным инструментированным операциям. Сумма записанных расходов **не равна полному счёту провайдера**.
- **Защищённая панель.** Пароль, сессионная cookie, проверка заголовка для изменяющих API-запросов, вход читателя по коду или QR; QR и видео доступны через защищённые маршруты.

## Два независимых потока

```text
Telegram-источники → общий читатель → посты выбранного пространства
    → LLM: факты + [пригодный условный ИИ-прогноз] + тематические теги
    → черновик с сохранённым каналом назначения
    → модерация в панели / боте → [очередь] → общий бот → канал

Тема + заметки + дата → контент-план выбранного пространства
    → LLM: статья + ограниченный JSON-сценарий одним ответом
    → [Pillow → FFmpeg → проверка ffprobe → MP4]
    → готовое задание → ручная или отдельная плановая публикация → канал

Веб-панель ↔ aiohttp API ↔ App / workspace-view ↔ SQLite
```

**Видео не синтезируется нейросетью по кадрам.** Модель пишет текст и сценарий; локальный CPU-рендерер Pillow/FFmpeg рисует ограниченную анимированную инфографику без GPU, озвучки, удалённых ассетов и исполнения модельного кода.

## Быстрый запуск

Основной целевой сценарий — Linux, Python 3.12 и один процесс приложения. Для MP4 нужны FFmpeg с `libx264`, ffprobe и шрифт Liberation Mono по ожидаемому пути. Точные Python-зависимости берутся из включённых файлов, а не из незакреплённых диапазонов версий.

```bash
python3.12 -m venv .venv
.venv/bin/python -I -m pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
# До запуска замените PANEL_PASSWORD на уникальный случайный пароль.
# Оставьте PANEL_HOST=127.0.0.1; секреты Telegram/LLM вводятся позже в панели.
env -u PYTHONPATH -u PYTHONHOME .venv/bin/python -B main.py
```

Панель в примере доступна локально на порту `8080`. Без установленного `PANEL_PASSWORD` приложение генерирует пароль и выводит его в журнал — для обычной эксплуатации так запускать не следует.

**Сразу поставьте новостное расписание на паузу перед подключением источников и LLM.** У исходной «Основной» области значение `paused` по умолчанию равно `0`; новый workspace создаётся с `paused=1`. После заполнения подключений основной планировщик может начать сбор без дополнительного нажатия. Пауза не запрещает ручную генерацию и не останавливает независимый контент-план.

Проверка HTTP без подключения к Telegram и LLM:

```bash
curl --fail http://127.0.0.1:8080/health
curl -i http://127.0.0.1:8080/api/state
```

Ожидаемый контракт: `/health` возвращает `ok`, API без входа — `401`. Это проверяет HTTP-панель, а не авторизацию читателя, работу платного API или публикацию в Telegram.

## Что важно не обещать

- Ссылки на Telegram-оригиналы не означают независимую проверку фактов. Совпадение сообщений нескольких каналов не доказывает достоверность события.
- Характер автора и ИИ-прогноз — редакционные инструкции и модельный вывод, не гарантия объективности или точности.
- Изоляция workspace защищает редакционные данные от смешивания в приложении, но не создаёт многопользовательскую систему с отдельными ролями и ключами.
- Обычная публикация не имеет гарантии exactly-once при неоднозначном сетевом сбое. У контент-плана такие отправки фиксируются как `uncertain` и не повторяются автоматически.
- Отчёты отражают сохранённые инструментированные операции, частично известные суммы и тарифные оценки. Старые/удалённые отчёты и неучтённые вызовы не восстанавливаются автоматически.
- Офлайн-тесты с подменой транспортов не подтверждают реальный вход по QR, платный ответ модели или доставку в Telegram.

Документация описывает код репозитория и контракт новых настроек прогноза. Она не содержит production-конфигурацию, учётные данные, базы, сессии или результаты живого приёмочного запуска. Репозиторий сохраняет частный режим; лицензия и право публичного распространения здесь не объявляются.
