# Установка и конфигурация

## Требования и границы инструкции

Целевой способ эксплуатации: Linux, Python 3.12, отдельный непривилегированный пользователь и **один** процесс. Motion-рендер использует Linux `/proc/self/fd`, `dir_fd` и `O_NOFOLLOW`; Windows/macOS для полной системы с MP4 этой инструкцией не заявляются проверенными. Виртуальное окружение из другой машины не копируйте.

`requirements.txt` включает три поставляемых снимка:

```text
requirements.lock.txt    — основное приложение и транзитивные зависимости
requirements-qr.txt      — qrcode==8.2
requirements-motion.txt  — Pillow==12.3.0
```

Это версии из исходников, не обещание доступности любой версии на произвольном зеркале. Не заменяйте их выдуманными номерами или незакреплёнными `>=` при ошибке установки: проверьте используемый индекс и совместимость интерпретатора. Anthropic вызывается через уже включённый `httpx2`; отдельный Anthropic SDK не требуется.

Все команды ниже — примеры для **своего** развёртывания. Они не устанавливают автоматически systemd, не создают Telegram-аккаунт и не включают генерацию. На существующей установке сначала [сделайте резервную копию](operations.md).

## Локальное окружение

Из корня checkout:

```bash
python3.12 -m venv .venv
.venv/bin/python -I -m pip install -r requirements.txt
.venv/bin/python -I -m pip check
cp .env.example .env
chmod 600 .env
```

Откройте `.env` локальным редактором и замените пароль. Уникальный случайный пароль должен быть существенно сильнее демонстрационной строки; шаблон сам по себе не является безопасным секретом. Не публикуйте содержимое `.env`.

| Переменная | Фактическое поведение |
| --- | --- |
| `PANEL_PASSWORD` | Пароль панели. Без значения пароль генерируется, сохраняется в БД и печатается в лог. Задавайте явно. |
| `PANEL_HOST` | Адрес bind. Исходный fallback — `0.0.0.0`; шаблон безопасно задаёт `127.0.0.1`. |
| `PANEL_PORT` | Целое число, исходный default `8080`. |
| `PANEL_URL` | Доступный оператору внешний URL без завершающего `/`; используется `/panel` в боте и определяет флаг Secure cookie при `https://`. |
| `DB_PATH` | Default `data/newsbot.db`. Относительный путь вычисляется относительно `config.py`, не текущей директории оболочки. |
| `TZ_NAME` | Default `Europe/Moscow`; часы расписания/тихих часов и ввод дат плана. При неверной зоне App использует UTC, поэтому проверяйте отображаемую зону. |

`.env` читается рядом с `config.py`. Уже заданные переменные окружения имеют приоритет. API ID/hash, токен бота, сессии и LLM-ключи — **не дополнительные `.env`-поля этого приложения**: они настраиваются в панели и хранятся в SQLite.

Запуск:

```bash
env -u PYTHONPATH -u PYTHONHOME .venv/bin/python -B main.py
```

Ключ `-B` не создаёт bytecode рядом с исходниками. Отсутствующие подключения дают статусы «не настроен», но панель может работать. При первом запуске схема/миграции БД создаются автоматически; это не автоматическое развёртывание сервера.

До подключения источников и LLM откройте панель и поставьте новости на паузу. «Основная» по умолчанию имеет `paused=0`, `auto_publish=0`; новые области — `paused=1`, `auto_publish=0`. План имеет `plan_paused=1` независимо от новостей. Нет env-переменной, которая заменяет эти workspace-флаги.

## FFmpeg, ffprobe и шрифт

Новостные тексты не требуют FFmpeg, но задания с видео без него не подготовятся. Python-зависимость Pillow не устанавливает системные бинарники.

Для Debian/Ubuntu в своём окружении:

```bash
sudo apt-get update
sudo apt-get install -y ffmpeg fonts-liberation
/usr/bin/ffmpeg -version
/usr/bin/ffprobe -version
test -r /usr/share/fonts/truetype/liberation/LiberationMono-Regular.ttf
/usr/bin/ffmpeg -hide_banner -h encoder=libx264
```

Проверяйте наличие `libx264` и **точный** путь шрифта: пакет с похожим названием может устанавливать шрифты в другое место. Renderer использует этот путь в константе `FONT`, а не настройку панели.

Для штатного PlanEngine бинарники должны быть обычными исполняемыми файлами по **заданным в коде** путям:

```bash
sudo install -d -o root -g root -m 755 /opt/newsbot/bin
sudo install -o root -g root -m 755 /usr/bin/ffmpeg /opt/newsbot/bin/ffmpeg
sudo install -o root -g root -m 755 /usr/bin/ffprobe /opt/newsbot/bin/ffprobe
/opt/newsbot/bin/ffmpeg -version
/opt/newsbot/bin/ffprobe -version
sha256sum /opt/newsbot/bin/ffmpeg /opt/newsbot/bin/ffprobe
```

Здесь `/opt/newsbot/bin` — реальный программный default, а не раскрытие конкретного сервера. `PATH` и выдуманные `FFMPEG_PATH` в `.env` его не заменяют. Renderer допускает явные абсолютные аргументы `ffmpeg_path/ffprobe_path` при прямом вызове/тесте; PlanEngine их не передаёт. Символические ссылки на исполняемые файлы отвергаются. После обновления системного FFmpeg повторно обновите локальные копии и проверьте результат; скопированный бинарник сам не обновится. Для динамической сборки нужны её совместимые системные библиотеки.

## Первичное подключение через панель

1. **Пароль и пауза.** Войдите в локальную/защищённую панель, приостановите новости, проверьте выключенную обычную и срочную автопубликацию. План оставьте на паузе.
2. **Telegram API.** Введите свои `api_id/api_hash`, полученные для Telegram-приложения.
3. **Читатель.** Введите свой номер и код, затем пароль 2FA, если Telegram его запросит; либо явно нажмите вход по QR и подтвердите в своём Telegram-клиенте. Вид доставки кода сообщает Telegram — успешный HTTP-запрос не доказывает доставку сообщения. QR формируется локально, токен входа не отправляется внешнему QR-сервису.
4. **Бот.** Укажите отдельный токен предназначенного для этой установки бота. Не запускайте конкурирующий процесс для того же бота.
5. **Администратор.** Откройте личную ссылку привязки из панели и нажмите Start; либо задайте собственные ID через доступные настройки. Эта ссылка секретна по назначению — не включайте её в README, тикет или снимок экрана.
6. **Назначение.** В выбранном workspace задайте канал публикации. Добавьте бота администратором с правом публикации сообщений и выполните проверку назначения.
7. **LLM.** В общих подключениях выберите OpenAI, DeepSeek, OpenRouter либо custom OpenAI-совместимый endpoint и ключ. В workspace выберите модель. Проверка подключения делает настоящий completion и может стоить денег. Даже custom-провайдер ожидает непустой API key; для локального сервера без авторизации используйте только допустимую ему условную строку, а не чужой секрет.
8. **Источники и редакция.** Добавьте доступные читателю каналы, задайте текстовые настройки, прогноз, длину/интервал. Не снимайте паузу и не запускайте сбор до согласования расходов и проверки канала.

Секретные поля в state не возвращаются полностью; пустое поле секрета при сохранении означает «не менять», а не удаление ключа. Сам SQLite всё равно содержит действующие секреты.

Для плана provider `shared` использует общий news endpoint/key, а `plan_model` может отличаться. Provider `anthropic` использует отдельный общий plan-key и workspace `plan_model`; news-подключение не заменяется. Цены вводите только если известны: пустой тариф корректнее выдуманного нуля.

## Linux/systemd: пример с read-only кодом

Ниже выбран условный каталог приложения `/opt/newsbot` и отдельные runtime-данные `/var/lib/content-gen`. Путь исходников можно заменить в unit, но default-путь FFmpeg в коде остаётся `/opt/newsbot/bin`.

1. Оператор вручную размещает проверенный checkout в `/opt/newsbot`, создаёт там `.venv` и устанавливает зависимости. Исходники/venv/бинарники принадлежат root и не доступны для записи сервису. Не переносите туда чужие `.env`, БД, сессии, тестовые артефакты или venv.
2. Создайте системного пользователя и каталог конфигурации (один раз, только если они ещё не существуют):

```bash
sudo useradd --system --user-group --home-dir /var/lib/content-gen \
  --no-create-home --shell /usr/sbin/nologin contentgen
sudo install -d -o root -g root -m 700 /etc/content-gen
sudo install -o root -g root -m 600 .env.example /etc/content-gen/panel.env
sudoedit /etc/content-gen/panel.env
```

В `panel.env` **замените пароль**, оставьте `PANEL_HOST=127.0.0.1`, установите `DB_PATH=/var/lib/content-gen/newsbot.db`, `PANEL_PORT=8080` и свой фактический URL. Для TLS используйте `PANEL_URL=https://…`. Не используйте многоточие буквально. В EnvironmentFile systemd значение имеет приоритет над `Environment=` unit; оставленный `DB_PATH=data/newsbot.db` приведёт к попытке записи в read-only checkout.

3. Установите и проверьте шаблон:

```bash
sudo install -o root -g root -m 644 deploy/content-gen.service.example \
  /etc/systemd/system/content-gen.service
sudo systemd-analyze verify /etc/systemd/system/content-gen.service
sudo systemctl daemon-reload
sudo systemctl start content-gen.service
sudo systemctl status content-gen.service --no-pager
```

`StateDirectory=content-gen` создаёт сервису writable-каталог `0700`; `UMask=0077` ограничивает права новых данных. `ProtectSystem=strict`, `ProtectHome=true` и `ReadOnlyPaths=/opt/newsbot` оставляют код неизменяемым, `ReadWritePaths=/var/lib/content-gen` разрешает БД, фото и MP4. Приватный временный каталог systemd не превращает исходники в writable. Unit не блокирует сеть полностью: Telegram и API нуждаются в исходящих соединениях.

Откройте локальную панель безопасным способом, задайте паузы и подключения. Включать автозапуск ОС стоит после проверки конфигурации:

```bash
sudo systemctl enable content-gen.service
curl --fail http://127.0.0.1:8080/health
curl -i http://127.0.0.1:8080/api/state
```

Проверьте runtime-права на весь путь данных, особенно родительский `media`, а не только дочерние workspace-папки. Не используйте blanket recursive `chmod 777` или владение кодом у сервиса. Рендер проверяйте непривилегированным UID и с production-подобным hardening; успешный запуск от root не доказывает работу unit.

## Доступ к панели

Для локального HTTP оставляйте loopback и используйте собственный SSH-туннель. Для сетевого доступа установите доверенный reverse proxy/TLS, не открывайте панель с Telegram-кодами на публичном HTTP.

Бэкенд обслуживает `/`, `/api/...` и `/health`. Если внешний URL имеет префикс, например `/news/`, proxy должен согласованно обслуживать HTML и все API, QR, медиа и MP4, переписывая префикс. Одного `PANEL_URL` недостаточно: в интерфейсе есть абсолютные `/api/...` ссылки. Не используйте выдуманный скрытый auth-path как замену пароля. Proxy обязан перезаписывать недоверенный `X-Forwarded-For` адресом реального клиента.

После изменения `panel.env` перезапустите только данный сервис. Установка файлов и HTTP-health — отдельные проверки от реального QR-входа, платной генерации и Telegram-публикации.
